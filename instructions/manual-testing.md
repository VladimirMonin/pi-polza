# Ручное тестирование pi-polza

Инструкция для агента и для человека. Разделяет две роли: **агент готовит проект**,
**человек запускает Pi и смотрит глазами**.

Причина такого разделения: запуск из папки с исходниками доказывает, что код работает,
но **не** доказывает, что плагин устанавливается. Для второй проверки нужна чистая папка,
где исходников нет.

---

## 1. Где что лежит

| Что | Путь |
|---|---|
| Исходники и разработка | `C:\PY\pi-polza-connection-plugin` |
| **Приёмочная среда** (как у стороннего пользователя) | `C:\PY\pi-polza-smoke-test` |
| Настройки Pi (там живёт список пакетов) | `C:\Users\User\.pi\agent\settings.json` |
| Кеш метаданных OpenRouter | `<проект>/.pi/pi-polza-cache/openrouter.json` |
| Сам плагин внутри репозитория | `.pi/extensions/pi-polza/` (27 файлов `.ts`) |

Приёмочная среда — **постоянная**, не временная. Она содержит только `.env` и `README.md`,
никаких исходников. Если её нет — создать:

```bash
mkdir -p "C:/PY/pi-polza-smoke-test"
cp "C:/PY/pi-polza-connection-plugin/.env" "C:/PY/pi-polza-smoke-test/.env"
```

## 2. Роли

### Агент делает

1. Правки в коде и документации.
2. `npm test` — тесты (должны быть зелёные).
3. `npm pack --dry-run` — проверка состава артефакта.
4. `pi install <путь>` — установка пакета.
5. Запись в `settings.json` — проверка, что пакет появился в списке.
6. Отдаёт человеку точные команды запуска.

### Агент НЕ делает

- **Не запускает Pi как пользователь.** TUI-интерфейс плохо управляется программно,
   и главное — проверка установки глазами нужна человеку, а не агенту.
- Не публикует пакет в npm (`"private": true` — намеренно).
- Не трогает `.env` с ключом без необходимости.
- Не правит файлы вне этого репозитория (кроме `settings.json` через `pi install`/`pi remove`).

### Человек делает

Запускает Pi из приёмочной среды, переключает модель, смотрит футер и команды.

## 3. Подготовка агентом — по шагам

### Шаг 1. Дерево должно быть чистым

```bash
cd C:/PY/pi-polza-connection-plugin
git status --porcelain    # пустой вывод = чисто
```

### Шаг 2. Тесты

```bash
npm test
```

Ожидаемо: `tests 80`, `pass 80`, `fail 0`. Тесты офлайновые — без сети и без денег.

### Шаг 3. Проверка артефакта

```bash
npm pack --dry-run
```

Ожидаемо: `total files: 29`, около 33 КБ. Обязательно убедиться, что **не попали**:

| Не должно попасть | Почему |
|---|---|
| `.env` | там ключ |
| `artifacts/` | диагностические выгрузки, могут содержать данные счёта |
| `tests/`, `scripts/`, `notes/` | не нужны в рантайме |
| `pi-polza-*.tgz` | локальный артефакт, в `.gitignore` |

Внутри должно быть: `.pi/extensions/pi-polza/*.ts` (27 файлов), `package.json`, `README.md`.

### Шаг 4. Установка

```bash
pi install C:/PY/pi-polza-connection-plugin
```

Ожидаемо: `Installed C:/PY/pi-polza-connection-plugin`.

### Шаг 5. Проверить, что пакет в списке

```bash
pi list
```

Или посмотреть напрямую:

```bash
python3 -c "import json;print(json.load(open('C:/Users/User/.pi/agent/settings.json',encoding='utf-8')).get('packages'))"
```

В списке должна появиться запись на этот репозиторий.

### Шаг 6. Передать человеку команды запуска

```
cd C:\PY\pi-polza-smoke-test
pi
```

## 4. Что проверяет человек

### Обязательный минимум

| # | Что смотрим | Ожидаемо |
|---|---|---|
| 1 | Секция `[Extensions]` в стартовом баннере | есть `pi-polza` |
| 2 | Список моделей (`pi --list-models`) | 285 моделей с провайдером `polza` |
| 3 | Футер после запроса к модели Polza | `Polza <баланс> ₽ \| Session <стоимость> ₽` |
| 4 | `/polza-balance` | баланс, доступно, зарезервировано, потрачено за всё время |
| 5 | `/polza-cost` | стоимость текущей сессии |
| 6 | `/polza-model-info` | сведения о модели (только на Polza-модели) |
| 7 | `/polza-refresh` | перечитывает каталог моделей |

### Дополнительно

- обычный диалог и потоковая выдача (стриминг);
- вызов инструментов моделью;
- футер обновляется после каждого платного запроса;
- перезапуск Pi → стоимость сессии сохраняется;
- переоткрытие сессии → стоимость не удваивается;
- каталог моделей не пустой.

### Как выбрать модель Polza

В Pi набрать `/model`, затем в поиске `polza` — список отфильтруется.
Или сразу при запуске:

```powershell
pi --provider polza --model "bytedance-seed/seed-2.0-mini"
```

`bytedance-seed/seed-2.0-mini` выбран как дешёвый для проверки — один короткий запрос
стоит доли копейки.

## 5. Ловушки (проверены на практике)

### Pi не копирует локальный пакет

Запись в `settings.json` указывает **на сам репозиторий**, файлы никуда не копируются.
Следствия:

- после нового коммита переустанавливать не нужно — Pi читает рабочую копию;
- `pi update` этот пакет не трогает;
- если перенести репозиторий или `~/.pi`, путь поедет — нужно переустановить.

### В `settings.json` пишется относительный путь

При установке Pi записывает путь **относительно самого `settings.json`**, например
`..\..\..\..\PY\pi-polza-connection-plugin`. Это нормально, если `~/.pi` и `C:\PY`
не переезжают. Если переехали — переустановить с абсолютным путём.

### `.env` читается из текущей папки, а не из репозитория

Порядок поиска ключа:

1. переменная окружения `PI_POLZA_ENV_FILE` — явный путь к файлу;
2. `<текущая папка>/.env` — проект, откуда запущен Pi;
3. `<репозиторий>/.env` — только для разработки.

Значит запускать Pi нужно **из `C:\PY\pi-polza-smoke-test`**. Если запустить из другой
папки — ключ не найдётся, и появится `POLZA_API_KEY is missing`.

Обходной путь без `.env`:

```powershell
$env:POLZA_API_KEY="<ключ>"; pi
```

### `/polza-model-info` ругается на текущей модели

Ответ `Warning: Current model is not a Polza model (provider: ollama-cloud)` — это
**не ошибка**. Команда показывает сведения только о Polza-моделях. Нужно сначала
переключиться на модель Polza.

### Кеш создаётся в проекте потребителя

Файл `<приёмочная папка>/.pi/pi-polza-cache/openrouter.json` — признак того, что правка
работает. Если кеш появился внутри `C:\PY\pi-polza-connection-plugin`, значит плагин
вернулся к привязке на исходники — это регрессия.

## 6. Удаление и откат

```bash
pi remove C:/PY/pi-polza-connection-plugin
```

Проверить, что запись ушла из `settings.json`. Приёмочную папку можно не удалять —
она рассчитана на постоянное использование.

---

## 7. Стоп-критерии

Тест **не пройден**, если:

- `pi-polza` не появился в `[Extensions]` — пакет не установлен или манифест неверен;
- моделей с провайдером `polza` нет — каталог не загрузился (проверить ключ и сеть);
- футер не показывает рубли на Polza-модели — не работает учёт стоимости;
- появилось `POLZA_API_KEY is missing` — ключ не там, где ищется (см. ловушку про `.env`);
- кеш появился в папке с исходниками — регрессия привязки путей;
- `npm test` не зелёный — правки сломали существующее поведение.
