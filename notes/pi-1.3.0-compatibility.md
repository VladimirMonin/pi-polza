# pi-polza 0.2.1: совместимость с Pi Agent 1.3.0

## Статус и точные версии

Документировано 2026-10-19 по сохранённой проверке нативного runtime со **синтетическими
ответами**, без обращения к сервису Polza. Результат этого ограниченного контракта — PASS;
это не утверждение о полной готовности внешней сборки Pi или всех её компонентов.

| Компонент | Проверенная идентичность |
| --- | --- |
| Провайдер | `pi-polza` **0.2.1**, [commit cbc8a61262eb682fc61c9ab1b3b1ab72ef08f139](https://github.com/VladimirMonin/pi-polza/tree/cbc8a61262eb682fc61c9ab1b3b1ab72ef08f139), исходный релиз `v0.2.1` |
| Pi | `@earendil-works/pi-coding-agent` **1.3.0**, `pi-ai` и остальные пакеты core family — exact **1.3.0**, не смешанный graph |
| ОС / runtime | **Windows / Node.js 25.8.1** |

Код провайдера, `package.json`, версия и peer ranges в этой документационной правке не меняются.
Проверенная production-версия остаётся **0.2.1**; новый тег/релиз не создаётся.
Минимум Node.js в манифесте остаётся `>=22.6`, но это не означает, что весь диапазон заново
проверен. **Python не является требованием pi-polza.** Python 3.14.2 относится к отдельной
среде сборки, а не к контракту провайдера.

## Что именно выполнялось

Исполнялись установленный production-провайдер и настоящий нативный транспорт Pi 1.3.0,
а не только mock реализации Pi. Вместо ответа внешнего сервиса транспорт получал
детерминированный synthetic SSE. Сохранённый результат имеет scope
`PINNED_POLZA_REAL_PI130_TRANSPORT_SYNTHETIC_SSE` и три проверки:

| Проверка | Наблюдённый результат |
| --- | --- |
| `NATIVE_REASONING_TOOL_JSON_USAGE` | Блок `thinking` с `reasoning_content`; собранный tool call `echo` с JSON-аргументом `{ "value": 42 }`; `stopReason: toolUse`; usage: input 10, output 2, total 12 |
| `DONE_BEFORE_DELAYED_EOF` | Нативный поток завершился по `[DONE]` до отложенного закрытия HTTP body; учёт не ожидал EOF |
| `EXACTLY_ONCE_RUB_NOT_USD` | Ровно одна запись учёта с `costRub: 0.25`; все поля Pi `usage.cost`, включая `total`, остались `0` |

`0.25` — **синтетическое** значение `usage.cost_rub`, не реальное списание со счёта.
Слово «фактический» описывает источник стоимости в production-контракте: берётся переданное
Polza `usage.cost_rub`, а не оценка по ценам каталога или пересчёт валюты. В этой проверке
источник был заменён synthetic-ответом. Наличие блока reasoning не доказывает поддержку
всех уровней reasoning; вызов `echo` не является проверкой всех инструментов/моделей.

## Контракты в исходниках

- [Фабрика нативного транспорта](../.pi/extensions/pi-polza/stream.ts) делегирует Pi
  `openAICompletionsApi()` из `@earendil-works/pi-ai/compat`; собственный SSE/tool/reasoning
  транспорт не добавлен. Версии публичных пакетов:
  [Pi coding-agent 1.3.0](https://www.npmjs.com/package/@earendil-works/pi-coding-agent/v/1.3.0),
  [Pi AI 1.3.0](https://www.npmjs.com/package/@earendil-works/pi-ai/v/1.3.0).
- [Учёт поверх нативного observer](../.pi/extensions/pi-polza/stream-accounting.ts):
  `onProviderStreamEvent` сохраняет snapshot последнего raw usage до callback вызывающей стороны;
  исходный поток возвращается без замены. `stream.result()` запускает запись один раз после
  успешного терминального результата (`stop`, `length`, `toolUse`); ошибка/отмена не превращаются
  в известную стоимость.
- [Нормализация и аккумулятор](../.pi/extensions/pi-polza/accounting.ts) сохраняют неизвестную
  стоимость как `null`, а настоящий ноль как ноль;
  [mapper](../.pi/extensions/pi-polza/mapper.ts) не подменяет долларовые цены рублями.
- [Офлайн-контракт обёртки](../tests/stream-accounting.test.ts) проверяет её поведение отдельно
  от установленного SDK. [Нативные тесты репозитория](../tests/stream-native.test.ts) привязаны
  к **Pi 1.0.2** и его bundle layout: их skip без этого SDK нельзя выдавать за проверку Pi 1.3.0.
  Доказательство для 1.3.0 выше переиспользовано из отдельного выполненного native synthetic-прогона,
  а не получено переименованием этих тестов.

Ранние заметки [native-rub-accounting.md](native-rub-accounting.md) и
[streaming-accounting.md](streaming-accounting.md) описывают исторические fetch/tap-реализации.
Текущий контракт 0.2.1 для этой проверки — observer и terminal result в исходниках выше,
а не клонирование response или ожидание flush/EOF.

## Границы доказательств и воспроизведение

- В этой документационной задаче переиспользованы сохранённые runtime-результат и inventory
  точных установленных версий; новый native/runtime или live-прогон не запускался.
  Приватные профили, ключи, сырые логи и абсолютные локальные пути здесь не публикуются.
- Для локального офлайн-regression доступно `npm test` на подходящем Node.js. Результат нужно
  читать вместе со skip; один этот запуск **не** воспроизводит отдельный native 1.3.0 fixture.
  Для повторения именно контракта 1.3.0 нужны exact SDK 1.3.0, неизменённый провайдер 0.2.1,
  изолированная synthetic SSE подача и assertions из таблицы выше — без ключа и платных вызовов.
- Историческая пользовательская приёмка установленного исправления на **Pi 1.0.2** остаётся
  в [README](../README.md#совместимость) и [CHANGELOG](../CHANGELOG.md). Она не переносится
  автоматически на Pi 1.3.0.
- Не проверены здесь: live-сервис/тарификация Polza, визуальный TUI и новая пользовательская
  приёмка на 1.3.0, весь каталог/все модели, полный сценарий с подагентами, другие ОС/версии
  Node.js и все версии Pi 1.x. Полная live-совместимость не заявляется.
- Новый provider tag/release по-прежнему требует предусмотренного проектом
  [live-теста и release gates](../instructions/commit-and-release-guide.md#4-процесс-релиза).
  Эта docs/source-правка не отменяет их и не является npm-публикацией или новым релизом провайдера.
